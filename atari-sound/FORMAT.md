# PMS1 native music format

The longer ASMA remixes use **PMZ1**. It retains the PMS1 header/table layout and
register records described below, but compresses each entry stream with LZ:
tokens 0–127 precede `token+1` literal bytes; tokens 128–255 precede a little-endian
distance and copy `(token & 127)+3` bytes from the previous 1–4096 output bytes.
Overlapping matches are allowed. History resets at each entry. Encoded music loads
at `$4000` and may extend to `$BFFF`; the streaming decoder uses `$3000–$3FFF` for
history and `$F0–$F5` for pointers. BASIC is disabled by the XEX loader. The ordinary
PMS1 loader cannot play PMZ1; use its supplied `REMIX.XEX` or SAP instead.

PMZ1 is generated by `tools/long_music.py` using the shared player plus
`player/lz-reader.asm`. Seek entries may combine adjacent musical sections when
needed to fit 64K Atari RAM; the melody itself is not shortened.

All multibyte integers are little endian. A PMS file loads at `$4000` and is at
most `$7000` bytes long, ending no later than `$AFFF`. BASIC must be disabled.

| Offset | Length | Meaning |
| --- | --- | --- |
| `$000` | 4 | ASCII `PMS1` |
| `$004` | 1 | Version, 1 |
| `$005` | 1 | Entry count, 1–64 |
| `$006` | 2 | Reserved, zero |
| `$008` | 40 | Game title, Atari internal screen codes, space padded |
| `$030` | 16 | Reserved, zero |
| `$040` | 64 | Original pattern/SFX IDs |
| `$080` | 64 | Next local entry index; `$FF` stops |
| `$0C0` | 64 | Stream address low bytes |
| `$100` | 64 | Stream address high bytes |
| `$140` | variable | Compressed streams |

Each stream starts with a full register state. Records consist of a duration
byte (1–255 frames), a 16-bit change mask (only bits 0–8 allowed), then one byte
for each set bit in increasing bit order. Bits refer to `$D200`–`$D208`: AUDF1,
AUDC1, AUDF2, AUDC2, AUDF3, AUDC3, AUDF4, AUDC4 and AUDCTL. The state applies to
the current frame and the next `duration-1` frames. A lone zero byte ends the
stream, following the next-entry table on the same player call or silencing all
four volumes if the successor is `$FF`. There are no empty entry streams.

`source-music.json` is the original extracted score, not the PMS representation.
Each SFX has 32 `[pitch, waveform, volume, effect]` notes and speed/loop/filter
metadata; each music pattern has flags and four SFX IDs (64 means disabled).

## Player API

Assemble `player/player.asm` with MADS. Entry addresses other than `init` may
change; consult generated `player/player.lab` when linking.

- `init` at `$2000`: A = local entry index, initializes POKEY and selects it.
- `tick`: call once per PAL frame; decodes and writes up to nine POKEY registers.
- `silence`: mute all volumes without advancing the stream.
- Set `paused` to 1 to freeze tick advancement, then call `silence`; clear it to resume.
- `start`: standalone display and console-key application. Disables OS interrupts.

All routines clobber A/X/Y and flags. The decoder uses zero-page `$F0–$F1` and
private state within its own code segment. SAP Type B calls `init` through a
small shim at `$2F00`, which adds 0 or 32 to the requested subsong number, then
calls `tick` at normal PAL FASTPLAY=312. SAP contains the same assembled player
and PMS data as the XEX; it does not run the display or DOS loader.

The universal loader uses normal Atari CIO with IOCB 0 (console) and IOCB 1
(file) before transferring to `start`. It reads a generated PMS bank into RAM,
closes the file, and checks its magic/version/count. PMS is a trusted build
artifact; the small Atari loader is not a general untrusted-file validator.
